# RQ016C：只用纯人-人样本构建的 OnSite 参照 envelope（知识层）

状态：**构建完成并经监督方独立复算；产物已在真实 OnSite 行上验证可打分；尚无已接受的手稿主张（无 `decision.md`）**

执行层：`reports/studies/RQ016C_human_only_envelope/RQ016C_1_human_only_envelope_20260804T005716Z_7480c173/`

## 问题与 PI 裁定

在线验证要判断一辆自动驾驶车表现出的社会交互倾向像不像人。机制二拿通过机制一的 IPV 数值与
人类参照分布（envelope）比。RQ016B 查实：RQ016 重建的那个 envelope 里 10.9009%
（69,288/635,618）的目标值是自动驾驶车自己的 IPV。

**PI 裁定（2026-08-04）**：envelope 是建在数据分布之上的**查询机制**，针对不同目标可以建
不同的 envelope。本研究要问「OnSite 的自动驾驶车的 IPV 是否落在人类的分布范围内」，
参照对象就应当是**纯人类**的 IPV 分布。故只用 E3（纯人-人）重建一个供 OnSite 使用的 envelope。

## 构建口径

参照池 = 台账覆盖（只含 development + guard）∩ 机制一通过（`status == "OK"`）∩
`agent_type_pair == "HV;HV"`，共 **2,442,625 行**（development 1,752,509 + guard 690,116，
held_out 实测 0）；分 fold train 974,984 / calibration 481,088 / guard_tune 499,893 / test 486,660。

**特征集相对 RQ009 M2 有一处必要修改**：移除 `agent_type_pair`、`av_included`、
`vehicle_type_list` 三列。理由是车辆是否为自动驾驶车是**被检验的对象**而非它所处的情境；
且 OnSite 在这三列上的取值在纯人类训练池中从未出现（`vehicle_type_list` 含 `AV` 的训练行
为 0/2,442,625，而 OnSite 全部 67,861 行都是 `['AV','HV']`），保留任一列都会使打分撞上未知类别。
最终为 22 项数值 + 4 项类别；支持门分格键 `geometry_path_category + priority_role`。

## 结论

**C1 — 纯人类 envelope 已建成并可用。** 90% 名义层 coverage 0.898038（414,837/461,937），
平均宽度 1.238468，机制二弃权率 5.0801%（24,723/486,660）。80/95 层见执行记录。
持久化产物可**只加载、不重新拟合**给外部行打分，自测 256 行区间边界逐位一致（max|Δ| = 0.0）。

**C2 — 打分管线已在真实 OnSite 全量行上跑通。** 67,861 行全部产出三层区间与支持门判定，
无 NaN、无负宽度。**这只证明管线可运行，不构成对任何一辆自动驾驶车的判定**——OnSite 一行都
没有机制一判据（`status`/`reason_code`/`mse_0..6` 在 281,268 行上非空计数全部为 0）。

**C3 — OnSite 只有约三分之一的帧在人类数据里有足够相近的情境。**
支持门通过 21,936/67,861 = **32.3249%**，逐格从 `F|priority` 的 47.03%（13,958/29,677）
到 `CP|equal` 的 0.00%（0/116）。落格由几何与优先权粗分，通过与否还要看运动学近邻。
**这不是缺陷，正是机制二该做的事**，但它实质性地改变了对 OnSite 应用产出量的预期：
两道门叠加后可判比例会明显低于三分之一。

## 效度边界

1. **与 RQ009 已发表数不构成复现关系**——域不同（仅 development + guard）且特征集已修改。
2. **无同源迁移证据**：RQ009 的 LODO 只含 4 个留出源，OnSite 不在其中。
3. **OnSite 存在坐标系异常**：7 行（0.0103%）的 `relative_distance_anchor` ≈ 570,761.6 米，
   由单侧 `relative_dx_anchor` 异常导致。量极小，但真正做 OnSite 分析前须处理。
4. `apet_online_proxy` 填充率 OnSite 7.90% 对 InterHub 40.26%。
5. 描述性结果，不构成因果主张。禁用 `estimability` 与「测出/未测出 IPV」表述。

## 过程记录：一次规格错误与它的代价

首轮 H1 只移除了 `agent_type_pair` 与 `av_included`，漏掉 `vehicle_type_list`，
产物对 OnSite 的可打分行数为 **0/67,861**。**根因是监督方任务书的规格错误**
（把类别集写成「7 项减 2 项 = 5 项」），不是执行方的执行错误。H1 自己的负对照当时报
`UNEXPECTED_PASS`，即断言没有在检查它声称检查的东西——两道网同时失效。

修正轮 H2 新增三条验收，其中两条是针对性的：**类别词表覆盖断言**（OnSite 取值必须
100% 落在训练池已见取值内）与**真实 OnSite 全量打分演练**。前者若在 H1 时存在，
`vehicle_type_list` 的 0/67,861 会立刻暴露；后者是产物有效性的唯一证明——H1 的自测只用了
256 行人类数据，那批数据不会撞上未知类别，所以测不出这个缺陷。

**可操作教训**：当一个产物的用途是「给某个外部数据集打分」时，验收必须**用那个外部数据集
的真实行**跑通，不能用训练同源的样本自测。H1 的产物看起来每一项指标都正常。
