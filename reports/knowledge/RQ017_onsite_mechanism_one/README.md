# RQ017：在自动驾驶车数据上产出机制一判据，并首次量出两道门的实际可用率（知识层）

状态：**执行完成，结论已由监督方独立复算；尚无已接受的手稿主张（无 `decision.md`）**

执行层：`reports/studies/RQ017_onsite_mechanism_one/RQ017_1_onsite_gate_20260804T075311Z_406e7a65/`

## 问题

最终目标是**在线验证**：判断一辆自动驾驶车表现出的社会交互倾向像不像人。判定由两道串联
弃权机制构成——**机制一**判断某一帧的 IPV（Interaction Preference Value，表示交互倾向的
标量）数值是否携带七个候选之间的判别信息；**机制二**用人类参照分布判断当前情境是否有
足够人类样本可比。两关都过才可判。

RQ015 冻结机制一，RQ016C 建好纯人类参照分布。**但在 RQ017 之前，这套方法从未真正对准过
一辆自动驾驶车**——OnSite 的 281,268 行台账里机制一判据非空计数为 0。

**RQ017 问的是**：把机制一在自动驾驶车数据上真正算出来，两道门串联之后还剩多少可判。

## 结论

**A1 — 帧级可用率约五分之一。** 67,861 个自动驾驶车锚点帧中，两门都过的为
**14,099 = 20.7763%**。机制一挡掉 30,341 = 44.7029%（全部因权重近均匀）；
过了机制一又被机制二挡掉 23,421 = 34.5133%。

**A2 — Case 级可用率远高于帧级，且可估计性不是瓶颈。**
分母 267 个 case：至少 1 帧可判的 **231 个 = 86.5169%**；全程不可判的 36 个 = 13.4831%，
**其中因机制一全程无解的为 0 个 = 0.0000%**。
**没有任何一个 case 是全程无法估计 IPV 的。** 那 36 个 case 全部死于机制二无参照，
其机制一通过率 53.78%（与全体 55.30% 基本相同）、机制二通过率 0.07%（对全体 32.32%）。

**这条把结论的性质改变了**：真正的约束是人类参照的覆盖，而不是自动驾驶车轨迹的可估计性。
覆盖可以通过补人类数据改善；可估计性是数据本身的固有属性。

**A3 — 同一套机制一规则，在自动驾驶车数据上的弃权率高于人类数据。**
InterHub 4,981,984 个求解单元的 `OK` 为 70.3001%，OnSite 67,861 帧为 55.2971%。
即自动驾驶车的轨迹更难反推出交互倾向。**成因本轮未验证，不提供解释。**

**A4 — 机制二的缺口是重叠不是数量。** `MP|yield` 与 `MP|priority` 各有 1,148,133 /
1,044,964 行人类支撑，机制二通过率却只有 14.58% / 13.48%；`F|priority` 仅 45,283 行人类支撑，
通过率却达 47.03%。限制因素是自动驾驶车的运动学状态是否落在人类样本附近，不是人类样本数量。

## 效度边界

1. **`NO_IPV_EFFECT` 在 OnSite 上实际不可达**（0/67,861，最小非零 `mse_spread` 2.32e-08；
   InterHub 为 0.4007%，最小非零 4.77e-15，差七个数量级）。与观测轨迹 fallback 参考线合同一致。
   **OnSite 的弃权理由构成不可与 InterHub 对比，只能比总弃权率。**
2. **机制二比的是运动学邻域（12 项距离特征），不是 IPV 数值本身。
   「机制二不通过」只意味着无法判定，不得解读为「该车不像人」。**
3. **本轮不对任何车辆作出判断。**
4. 参考线用观测轨迹 fallback，与 InterHub 不同源；可比性由「同一估计器、同一冻结配置、
   同一软件栈」保证（G 锚点重算 `max_abs_diff = 0.0`），不由参考线来源保证。
5. 无同源迁移证据：RQ009 的 LODO 只含 4 个留出源，OnSite 不在其中。
6. **未解释的观察**：短历史行（1,572 行）机制一通过率 73.92%，高于满历史行 54.85%，
   方向与直觉相反。
7. 描述性结果，不构成因果主张。

## 过程记录：一次公开失败的预测

监督方在执行前**预注册**了预测（时间戳 `2026-08-04T06:22:47Z`，早于派发）：
用 OnSite 上 2,974 行旧估计器 `q_eff` 按 InterHub 的映射重加权，预测机制一通过率 ≈ 80%
（区间 65%–85%）。**实测 55.2971%，落在区间之外，预测失败。**

失败原因正是预注册时同时写下的那条弱点：用于校准的 2,974 行来自 `max_anchors_per_unit=1`
年代，锚点是被选出来的、系统性更有交互，把预测抬高。校准方法本身可用（回代 InterHub
得 70.3% 对实际 70.30%），坏在样本不具代表性。

漏斗预测（11,000–18,000）虽然覆盖了实测的 14,099，但那是两处误差部分抵消，
**不构成预测成功**。

**可操作教训**：从一个「被挑选出来的子集」外推到全集时，即使外推方法在源域上自洽，
选择效应仍会整体平移结果。预注册的价值在于这次失败是可见的、方向是事先写明的。

## 方法学：四轮任务书与两轮双盲复审

任务书 v1→v4，其中 v1（本机）、v2（本机 + 测量合同）、v3（HPC）均未执行。
两轮独立双盲复审各暴露一批缺陷：

- 第一轮（对 v2）：两位复审**独立收敛**于同一条主要意见——把输入/测量合同提到 canary
  之前写成会 FAIL 的断言。因为输入适配层错了会产出「七个 MSE 有限、权重和为 1、
  门判据可复算、恒等式成立」的结果，**所有既有检查都会通过**，但解的是错的行。
- 第二轮（对 v3）：发现 v3 漏掉 `PYTHONPATH` 与 `pydeps`（冻结环境没有 pyarrow，
  照 v3 写第一次写 parquet 就崩）、环境同源只要求「记录并比对」太软、机制二交叉未限定
  连接列（现成打分脚本是整表读取，会拉进 9 个旧估计器通道与目标值列）。

**venue 从本机改为 HPC 是 PI 提出的**，理由最终确定为产物来源一致性而非速度：
Mac 与 HPC 的求解结果在 81.17% 的锚点上不同。
